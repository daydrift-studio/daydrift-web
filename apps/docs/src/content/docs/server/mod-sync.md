在多人联机同游环境中，模组不仅影响本地客户端的表现，更承担着跨网络状态同步的责任。《度日：Daydrift》设计了一套轻量、安全且具备容错能力的网络模组同步协议。

---

## 1. 模组网络同步策略 (`net_sync_mode`)

在模组的 `manifest.json` 中，创作者通过 `net_sync_mode` 指定其网络行为：

1. **`client_only`（仅客户端）**：
   - 纯本地表现型模组（例如只替换了主角卧室的窗帘贴图、背景音乐或追加单人本地剧情切片）；
   - 服务端无需安装该模组，客机即使安装也不会向其他同游旅人广播数据；
   - 自由度最高，客机即插即用。
2. **`server_only`（仅服务端）**：
   - 纯后台管理型模组（例如服务端自动日志归档、敏感词过滤拦截、定时播报公告）；
   - 客户端无需安装，完全由服务端沙盒独立驱动。
3. **`dual_sided`（双端同步）**：
   - 具备联网状态交互的模组（例如全员共享天气系统、联机手冲咖啡小摊、自定义表情互动）；
   - 要求服务端与客户端均加载对应脚本；
   - 客户端与服务端通过自定义网络信道（Channel）双向收发自定义报文。

---

## 2. 客户端接入握手协商机制 (Handshake Phase)

当客户端尝试连接独立服务端时，必须经历严格的握手协议流：

```text
客户端                                服务端
  │                                     │
  ├─────── 1. 发送连接握手包 ─────────>│ (包含客户端版本号、协议版本与玩家凭据)
  │                                     │
  │<────── 2. 服务端响应挑战包 ────────┤ (包含服务器信息、世界时钟与模组清单要求)
  │                                     │
  ├─────── 3. 发送模组一致性响应 ──────>│ (上报客户端当前已激活模组及版本)
  │                                     │
  │<────── 4. 确认通过 / 拒绝接入 ─────┤ (若 require_exact_mods 开启且不匹配则拒绝)
  │                                     │
  ├─────── 5. 进入常规游戏状态同步 ────>│ (开始周期性位置同步与漫步交互)
```

- 若服务端开启了 `require_exact_mods = true`，当检测到客户端缺少标有 `dual_sided` 的核心模组或版本号不一致时，服务端将返回错误码 `ERR_MOD_MISMATCH`，并向客户端返回缺失的模组名称与所需版本号提示；
- 若未开启严格模组锁，服务端将允许客户端进入，但自动禁用该客户端未安装的模组网络信道。

## 3. 自定义网络信道与 OpCode 报文路由

所有模组网络通信均被封装在专用的网络操作码 `OP_MOD_PACKET`（操作码 `0x30`）内部：

### 报文帧结构

```text
+---------------+----------------+------------------+-----------------------+
| OpCode (1B)   | Channel Len(1B)| Channel Name(UTF)| Payload JSON Bytes(N) |
| 0x30          | 例如 0x0c      | "coffee_cheer"   | {"mood":"relaxed"}    |
+---------------+----------------+------------------+-----------------------+
```

### 转发流转规则
1. **客户端 -> 服务端**：客户端调用 `ModAPI.send_net_packet(channel, payload)` 发送报文，服务端沙盒捕获并触发 `on_net_packet(peer_id, channel, payload)` 回调；
2. **服务端单播**：服务端调用 `ServerAPI.Net.send(peer_id, channel, payload)`，直接路由给目标玩家；
3. **服务端广播**：服务端调用 `ServerAPI.Net.broadcast(channel, payload)`，由服务端内核遍历房间在线连接池高效分发。

---

## 4. 服务端公共黑板权威同步

为了避免客户端状态欺诈或不一致，《度日》采用**服务端权威状态黑板（Server-Authoritative Blackboard）**机制：
- 关键状态（例如当前全镇天气、特定事件触发标志）必须由服务端 Lua 脚本调用 `ServerAPI.Blackboard.set(key, value, true)` 写入；
- 服务端底层自动将变更推送到所有在线客户端的本地黑板镜像中；
- 客户端脚本通过只读或请求方式查询该状态，保证所有旅人所见的世界状态始终精准契合。
